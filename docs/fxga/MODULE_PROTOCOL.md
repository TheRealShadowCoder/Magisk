# FXGA per-module configuration protocol (schema v1)

Standard Magisk modules **do not have a universal settings UI format**. FXGA supplies an **opt-in** manifest format. Every installed module has a read-only details menu even without it. A schema-enabled module has editable controls.

## Required module files

Place these files inside `/data/adb/modules/<module-id>/` as part of the installed module:

| File | Description |
|---|---|
| `module.prop` | Standard Magisk module metadata; Magisk already requires this. |
| `fxga-settings.json` | Optional, root-owned FXGA settings manifest. **Never store secrets here**. |
| `fxga-settings.conf` | Generated by the FXGA manager upon saving; UTF-8 `key=value` pairs, mode `0600`. |
| `action.sh` | Optional standard Magisk action; the FXGA settings UI never executes it. |

Example `fxga-settings.json`:

```json
{
  "schema": 1,
  "settings": [
    {"key": "enabled", "label": "Enable feature", "type": "toggle", "default": true},
    {"key": "profile", "label": "Module profile", "type": "select", "options": ["stable", "balanced", "debug"], "default": "stable"},
    {"key": "log_level", "label": "Log level", "type": "integer", "min": 0, "max": 3, "default": 1}
  ]
}
```

## Check a manifest before publishing

```sh
python tools/fxga/validate_manifest.py docs/fxga/examples/fxga-settings.json
python tools/fxga/validate_manifest.py --self-test
```

The developer validator is supplementary. The Android manager validates the same supported fields again before writing.

## Parsing and constraints

- Schema version is exactly `1`; maximum **40** settings.
- Each `key` is unique and matches `[A-Za-z][A-Za-z0-9_]{0,63}`.
- Types: `toggle` (`true`/`false`), `select` (1–16 safe options), `integer` (bounded integer).
- Select options match `[A-Za-z0-9_.:-]{1,48}`; no shell metacharacters, spaces, slash or newline.
- Numeric bounds must be within `-100000..100000`; the default must fall within the bounds.
- Module IDs are derived from verified installed module directory names and validated before constructing any shell path.
- Extra config entries are ignored by the manager. Only declared, valid values render in the UI.
- Invalid/unknown manifest schemas produce a diagnostic warning, not an executable fallback.

## Write contract

On Save, the manager validates every value again and replaces `fxga-settings.conf` using a temporary file with mode `0600`. The operation uses a root-authorized shell, fixed paths and Base64 transfer of **validated** key/value lines; it never executes scripts from the manifest or interpolates arbitrary text into shell commands.

**The module author must implement loading this file.** For example, inside the module's own boot script:

```sh
CFG=/data/adb/modules/example_module/fxga-settings.conf
enabled=true
profile=stable
log_level=1
if [ -f "$CFG" ]; then
    while IFS='=' read -r key value; do
        case "$key" in
            enabled) case "$value" in true|false) enabled=$value;; esac ;;
            profile) case "$value" in stable|balanced|debug) profile=$value;; esac ;;
            log_level) case "$value" in 0|1|2|3) log_level=$value;; esac ;;
        esac
    done < "$CFG"
fi
```

Never `source` / `.` the generated file blindly: the protocol is **data**, not shell script, and the reader must validate allowed values.

## Lifecycle and UI behavior

- Settings may require restarting the affected module/app or rebooting; the app cannot promise immediate application.
- Disabling, uninstalling, upgrading or rolling back the module is still handled by normal Magisk module management.
- A missing manifest produces a details menu only; there is no automatic reverse engineering of arbitrary module private configuration.
- No embedded web server, `WebUI` execution, HTML injection or `action.sh` invocation in schema v1.
- Secrets, credentials, private app data, and unsafe settings types are out of scope.
- Authors should include an example manifest and test each value on Android 17/API 37 if claiming support.

## Backward compatibility

This protocol is FXGA-specific. It doesn't change Magisk's native module ABI, Zygisk library loading, or existing module directory layout. Modules that do not opt in continue to work as before, subject to their own Android compatibility.
